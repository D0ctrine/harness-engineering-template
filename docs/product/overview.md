# Juyaro Bible Project - Product Overview

## 1. Objective

Juyaro Bible Project는 사용자가 짧은 시간 안에 성경 본문을 읽고, 자신의 생각을 기록하고, 다른 사람과 묵상을 나눌 수 있도록 돕는 모바일 중심 PWA 서비스이다.

이 제품의 핵심 목표는 바쁜 일상 속에서도 사용자가 부담 없이 말씀을 접하고, 자연스럽게 기록하며, 필요할 때 공동체 안에서 묵상을 공유할 수 있게 만드는 것이다.

특히 사용자는 5분, 10분, 30분 단위의 QT 흐름을 선택할 수 있어야 하며, 읽기 → 메모 → 질문 → 나눔의 흐름이 자연스럽게 이어져야 한다.

---

## 2. Core Features

### 2.1 QT (정해진 본문 성경 읽기)

QT 기능은 사용자가 정해진 본문을 기준으로 짧게 성경을 읽을 수 있도록 제공한다.

주요 요구사항:

* 정해진 본문 기반으로 제공한다.
* 사용자는 5분, 10분, 30분 중 하나를 선택할 수 있다.
* 각 QT는 본문, 짧은 해설, 필요한 경우 묵상 질문으로 구성된다.
* 사용자는 앱을 열었을 때 복잡한 탐색 없이 바로 읽기를 시작할 수 있어야 한다.

핵심 의도:

* 생각 없이 열어도 바로 읽을 수 있는 경험
* 짧은 시간에도 완료 가능한 구조
* 읽기 자체에 집중할 수 있는 단순한 UX

---

### 2.2 메모 (QT와 연결된 기록 기능)

메모 기능은 QT 화면과 자연스럽게 연결되어 사용자가 본문을 읽으면서 바로 기록할 수 있도록 한다.

주요 요구사항:

* QT와 동일한 흐름 안에서 메모를 작성할 수 있어야 한다.
* PWA의 반응형 구조를 고려한다.

  * 넓은 화면에서는 왼쪽에 본문, 오른쪽에 메모를 함께 표시한다.
  * 모바일 환경에서는 본문 아래에 메모 영역을 배치한다.
* 메모는 해당 날짜와 본문 기준으로 저장된다.
* 초기 MVP에서는 텍스트 메모 중심으로 시작한다.

핵심 의도:

* 읽기와 기록이 분리되지 않도록 한다.
* 별도 화면 이동 없이 자연스럽게 메모하게 한다.
* 모바일과 큰 화면 모두에서 불편하지 않게 사용 가능해야 한다.

---

### 2.3 묵상 질문

묵상 질문 기능은 QT 본문과 메모 이후, 사용자가 한 번 더 생각을 정리할 수 있도록 돕는 단계이다.

주요 요구사항:

* 질문은 본문 읽기와 메모 이후 다음 단계에서 제공한다.
* 질문 화면은 별도 페이지 또는 다음 단계 화면으로 구성한다.
* 사용자는 질문에 대한 짧은 답변을 작성할 수 있다.
* 질문은 QT 내용을 더 깊이 생각하게 만드는 용도로 사용한다.

핵심 의도:

* 읽기와 기록 다음에 생각을 정리하는 단계 제공
* 한 화면에 모든 것을 몰아넣지 않고 흐름을 나눈다
* 사용자가 부담 없이 답할 수 있는 구조로 설계한다

---

### 2.4 묵상 나눔 (그룹 기반 커뮤니티)

묵상 나눔 기능은 사용자가 특정 그룹 안에서 자신의 묵상을 글과 이미지로 공유하고, 다른 사람의 글에 댓글 형태로 소통할 수 있게 한다.

주요 요구사항:

* 특정 그룹 방 안에서만 게시글을 작성하고 볼 수 있어야 한다.
* 트위터 스타일의 피드 구조를 사용한다.
* 게시글에는 텍스트와 이미지를 함께 올릴 수 있다.
* 다른 사용자는 댓글 또는 답글 형태로 반응할 수 있다.
* 나눔 기능은 강제가 아니라 선택적으로 사용된다.

핵심 의도:

* 개인 묵상을 공동체 경험으로 확장
* 가볍게 올리고 가볍게 반응할 수 있는 구조
* 실시간 채팅이 아닌 비동기형 커뮤니티 경험 제공

---

## 3. Product Flow

이 제품의 기본 사용자 흐름은 아래와 같다.

1. 사용자가 QT 시간을 선택한다.
2. 정해진 본문을 읽는다.
3. 같은 흐름 안에서 메모를 작성한다.
4. 다음 단계에서 묵상 질문을 확인하고 답변한다.
5. 원할 경우 그룹 방에 묵상을 공유한다.

이 흐름에서 중요한 점은 읽기, 기록, 질문, 나눔이 서로 분리된 기능이 아니라 하나의 자연스러운 경험으로 이어져야 한다는 것이다.

---

## 4. UX Principles

### 4.1 바로 시작할 수 있어야 한다

앱을 열었을 때 복잡한 메뉴 탐색보다 바로 QT를 시작할 수 있어야 한다.

### 4.2 읽기와 기록은 같은 흐름 안에 있어야 한다

본문을 읽다가 메모를 위해 다른 화면으로 크게 이동하면 안 된다.

### 4.3 반응형 구조가 명확해야 한다

* 데스크탑/태블릿: 본문과 메모를 좌우로 함께 배치
* 모바일: 본문 아래에 메모를 배치

### 4.4 질문은 다음 단계로 분리한다

질문은 본문과 메모를 방해하지 않도록 다음 페이지 또는 다음 단계에서 제공한다.

### 4.5 나눔은 선택이어야 한다

모든 사용자가 공유를 원하지는 않기 때문에 나눔 기능은 선택적으로 제공한다.

---

## 5. Non-Goals

초기 MVP에서는 아래 기능을 목표로 하지 않는다.

* 전체 성경 검색 기능
* 다양한 성경 번역본 제공
* 복잡한 북마크/태그 시스템
* 실시간 채팅 및 웹소켓 기반 상호작용
* 팔로우, 추천 알고리즘, 좋아요 중심의 소셜 네트워크 구조
* AI 자동 묵상 생성
* 과도한 화면 커스터마이징

초기 버전은 QT, 메모, 질문, 그룹 나눔이라는 핵심 경험에만 집중한다.

---

## 6. Success Criteria

MVP의 성공은 단순히 기능 구현 여부가 아니라 실제 사용 흐름이 잘 작동하는지로 판단한다.

### Activation

* 신규 사용자가 첫 방문 후 QT를 1회 이상 완료한다.
* 신규 사용자가 메모를 1회 이상 작성한다.

### Engagement

* 사용자가 3일 이상 반복해서 QT를 수행한다.
* QT 대비 메모 작성 비율이 일정 수준 이상 유지된다.
* 묵상 질문까지 완료하는 사용자가 존재한다.

### Social

* 그룹 방 안에서 묵상 게시글이 작성된다.
* 게시글에 댓글 또는 답글이 발생한다.
* 개인 기록이 공동체 나눔으로 자연스럽게 이어진다.

---

## 7. Initial Scope Summary

초기 MVP에서 가장 먼저 구현할 기능은 다음과 같다.

1. 정해진 본문 기반 QT 읽기
2. QT와 연결된 메모 작성 기능
3. 다음 단계의 묵상 질문 기능
4. 그룹 기반 묵상 나눔 피드

이 범위를 벗어나는 기능은 이후 사용자 반응을 본 뒤 확장한다.
